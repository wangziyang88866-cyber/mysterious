# 源堡（Source Castle）架构

`mysterious:source_castle` 是维度的稳定注册名，中文名称为“源堡”。“灰雾之上”保留作后续天空、区域或阶段名称；不要同时作为第二个维度 ID，避免存档和数据包兼容问题。

## 归属与多人

每个可占有区域使用一个 `RealmOwner` 作为唯一所有权键：未安装 FTB Teams 时为玩家 UUID；完成可选适配器后，安装 FTB Teams 时由 `RealmOwnerResolver` 返回 FTB 队伍 UUID。一个真实维度中会按固定间距分配多个 Arena，而不是按玩家动态注册维度。

```text
玩家施放“进入源堡”法术
        │
        ▼
RealmOwnerResolver ──无 FTB Teams──► PLAYER + 玩家 UUID
        │
        └──有 FTB Teams─────────────► FTB_TEAM + 队伍 UUID
                                           │
                                           ▼
                                  RealmSavedData / RealmRecord
                                           │
                    未分配 Arena ────────┼────── 已分配 Arena
                         │                │            │
                         ▼                ▼            ▼
                  创建区域与入口       传送入口      EncounterController
```

`RealmRecord` 必须持久化：所有者、成员/权限、Arena 坐标、返回点、当前战斗 ID、是否已完成首领战和战利品领取状态。队伍解散或 FTB Teams 卸载时，已有记录不丢失；它们应退化为锁定的 UUID 所有者记录，管理员可迁移归属。

## 战斗安全边界

`EncounterController` 是唯一能改变全局战斗状态的服务端对象。阶段 1 已建立服务器级唯一实例、Encounter 生命周期、BossRegistry 和幂等 Finalize；阶段 3/4 已为稳定字段接入网络投影、诊断与版本化 SavedData。后续阶段会逐步加入完整参与者行为、召唤物、托管装备与奖励状态。实体 AI 只能上报观察或请求技能执行，不能直接决定阶段、删除玩家物品、发放奖励或判定胜负。

装备窃取采用持久化托管（escrow）：先保存物品、来源槽位和所有者，再清空主副手、盔甲和 Curios 槽位。Amon 显示或使用的是副本；原件不会只存于实体 NBT。失败、胜利、Boss 消失、玩家死亡、断线、服务端重启恢复都会通过同一恢复服务归还装备。背包已满或原槽不可用时才投递到玩家脚下或待领取容器。

ISS 复制规则只快照玩家已拥有的法术 ID 和允许复制的等级。白名单/黑名单、最大等级、最大复制数量和冷却由服务器配置管理；不得复制玩家完整能力 NBT、饰品效果或未知第三方法术状态。

## 配置和数据

| 内容 | 位置 | 原因 |
| --- | --- | --- |
| 进入法术的稀有度、冷却、法力消耗、启用状态 | ISS 配置 + 本模组服务器配置 | 服务器可控，ISS 的原生机制适配最好 |
| 合成配方 | `data/mysterious/recipe/` 数据包 JSON | 可被整合包覆盖和热重载 |
| 战利品内容与权重 | `data/mysterious/loot_table/battle/` | 原版战利品表生态可直接复用 |
| 默认战利品表、个人/队伍分发、额外倍率 | 本模组服务器配置 | 是服务器规则而非物品定义 |
| 领域大小、Arena 间距、成员限制、失败恢复策略 | 本模组服务器配置 | 防止多人空间冲突 |

## 实施顺序

1. 修复 GeckoLib 资源路径并验证三个实体可在客户端渲染。
2. 实现 `RealmSavedData`、Arena 分配、传送与原位置返回；不包含世界生成和天空盒。
3. 完成个人所有权，再实现受 `ModList` 隔离的 FTB Teams 适配器。
4. 注册 ISS 进入源堡法术和服务器配置。
5. 扩展 `EncounterController` 的参与者生命周期和崩服恢复；核心生命周期与 Registry 已在阶段 1 完成。
6. 实现主副手、盔甲、Curios 的托管/归还，并完成断线与死亡测试。
7. 增加 Amon 阶段、召唤物、ISS 法术和受保护效果。
8. 增加法术复制、战利品、战后归属与客户端原版粒子/声音表现。

维度世界生成、天空盒、地形和结构放在第 2 步之后的独立迭代；它们不应阻塞 Arena、战斗或所有权数据模型。
